# 03. FRONTEND CODE & COMPONENT AUDIT
**Project:** RebarOptima SaaS  
**Audit Date:** November 2026  
**Auditor:** Principal Frontend Engineer & React Architect  
**Status:** Audit Only — No Code Modifications

---

## 1. Executive Summary

The RebarOptima frontend is built with **React 19**, **Redux Toolkit**, and **Vite**. While the application delivers modern, rich dark-mode aesthetics and responsive interaction, the frontend codebase exhibits several structural risks:
1. **Monolithic state and router files** (`App.jsx` at 545 lines, `api.js` at 741 lines).
2. **Competing sources of truth** for active project context between Redux and multiple `localStorage` keys.
3. **Framework contamination** from embedded Vue 3 / Element Plus libraries in the CAD viewer.
4. **Missing automated tests** (0 frontend unit/component tests).

## 2. Detailed Frontend Findings

### Issue ID: REB-P1-003
- **Severity:** P1 (High Impact)
- **Category:** Frontend / State Management
- **Affected Files:**
  - `frontend/src/store/slices/projectSlice.js`
  - `frontend/src/utils/api.js` (lines 43–49)
  - `frontend/src/App.jsx` (lines 98–105)
  - `frontend/src/pages/ChatPage/ChatPage.jsx` (line 31)
  - `frontend/src/components/ProjectSelector/ProjectSelector.jsx`
- **Evidence:**
  In `api.js` line 46:
  ```javascript
  const projectHeader =
    headers['X-Project-Id'] ||
    activeProjectIdForApi ||
    (typeof localStorage !== 'undefined' ? localStorage.getItem('rebar_active_project_id') : null);
  ```
  In `ChatPage.jsx` line 31:
  ```javascript
  const currentProjectId = selectedProject?._id || selectedProject?.id || localStorage.getItem('selectedProjectId') || null;
  ```
  In `projectSlice.js`:
  ```javascript
  export const ACTIVE_PROJECT_KEY = 'rebar_active_project_id';
  ```
- **Problem:**
  Multiple divergent keys exist in `localStorage`: `'selectedProjectId'` vs `'rebar_active_project_id'` vs `'active_project_id'`. When a user switches projects via the top navbar, Redux updates `selectedProject`, but some components reading directly from outdated `localStorage` keys continue fetching data for the previous project.
- **Impact:**
  - Race conditions and stale state after project switching.
  - Risk of displaying or submitting data under the wrong project context.
- **Recommendation:**
  Enforce a single authoritative custom hook `useActiveProject()` that reads strictly from Redux state. Deprecate direct `localStorage.getItem` reads inside UI pages.

### Issue ID: REB-P2-002
- **Severity:** P2 (Medium)
- **Category:** Frontend / React Architecture
- **Affected Files:**
  - `frontend/src/App.jsx` (lines 371–540)
- **Evidence:**
  `App.jsx` uses a massive nested ternary tree spanning over 170 lines to conditionally mount 31 different page views based on `state.routing.view`.
- **Problem:**
  There is no standard router (like React Router 7 or TanStack Router). All 31 pages are eagerly imported at the top of `App.jsx` without code-splitting or dynamic `React.lazy()` imports.
- **Impact:**
  - The initial JavaScript bundle download is excessively large, increasing Time to Interactive (TTI) on mobile devices or slow site network connections.
  - Heavy modules like CAD, Three.js, and PDF generators are loaded even if a user is merely checking attendance or petty cash.
- **Recommendation:**
  Introduce `React.lazy()` and `Suspense` for page views, or migrate to React Router with route-level code splitting.

### Issue ID: REB-P2-003
- **Severity:** P2 (Medium)
- **Category:** Frontend / Code Quality
- **Affected Files:**
  - `frontend/src/pages/ChatPage/ChatPage.css` (1,936 lines)
  - `frontend/src/pages/DrawingsPage/DrawingsPage.css` (850+ lines)
- **Problem:**
  Oversized monolithic Vanilla CSS files with duplicate utility classes and repetitive component definitions.
- **Impact:**
  CSS bloat, specificity conflicts, and high maintenance difficulty.
- **Recommendation:**
  Break page CSS files into co-located component stylesheets (e.g., `MessageBubble.css`, `ChatSidebar.css`, `CADViewer.css`).

### Issue ID: REB-P3-001
- **Severity:** P3 (Low)
- **Category:** Frontend / React Hook Dependencies
- **Affected Files:**
  - `frontend/src/pages/ChatPage/components/ChatWindow.jsx` (line 106)
  - `frontend/src/pages/ChatPage/components/NewGroupModal.jsx` (line 20)
  - `frontend/src/pages/ChatPage/components/MediaSendModal.jsx` (line 95)
- **Evidence:**
  Oxlint static analysis flagged 12 warnings regarding missing `useEffect` dependencies (`loadCandidates`, `loadInitialFiles`, `currentUserId`).
- **Problem:**
  Stale closures in callbacks inside `useEffect` can cause handlers to capture older props or state values.
- **Impact:**
  Potential intermittent bugs during rapid UI interactions or modal open/close transitions.
- **Recommendation:**
  Include referenced functions inside `useCallback` or add them to dependency arrays with appropriate ref safeguards.
