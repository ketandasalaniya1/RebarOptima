# 05. COMPREHENSIVE DUPLICATION AUDIT
**Project:** RebarOptima SaaS  
**Audit Date:** November 2026  
**Auditor:** Principal Software Architect & QA Lead  
**Status:** Audit Only — No Code Modifications

---

## 1. Executive Summary

This audit identifies functional, structural, and data duplication across all tiers of RebarOptima.

Duplication is classified into:
1. **Module & Business Domain Duplication**
2. **Backend Controller & Service Duplication**
3. **Database Schema & Collection Duplication**
4. **Reporting Engine Duplication**

---

## 2. Key Duplication Findings

### Issue ID: REB-P1-005
- **Severity:** P1 (High Impact)
- **Category:** Duplication / Database / Domain Model
- **Title:** Quadruplicate "Block / Wing" Domain Entities Across 5 Collections
- **Affected Files:**
  - `backend/src/projects/project-blocks.service.ts` (`project_blocks` collection)
  - `backend/src/casting/casting.routes.ts` (`casting_blocks` collection)
  - `backend/src/bbs/bbs.routes.ts` (`bbs_blocks` collection)
  - `backend/src/crm/crm.project-unit.routes.ts` (`crm_blocks` collection)
  - `backend/src/bbs/schemas/block-wing.schema.ts` (`blockwings` Mongoose model)
- **Description:**
  A structural building block (e.g., "Tower A", "Wing 1") is represented independently in 4 distinct database collections and 1 dormant schema. There is no shared reference. When a site manager configures blocks in Project Settings, Casting, BBS, and CRM cannot see them unless users manually recreate the same block name in each module.
- **Potential Impact:**
  - Massive user friction and double data entry.
  - Inconsistent naming (e.g., "Tower-A" vs "Tower A" vs "Block A") breaking cross-module reports.
- **Recommended Consolidation:**
  Designate `project_blocks` as the sole canonical source of truth. All downstream modules (BBS, Casting, CRM, Drawings) should store `blockId: ObjectId` referencing `project_blocks._id`.

### Issue ID: REB-P1-006
- **Severity:** P1 (High Impact)
- **Category:** Duplication / Frontend / Business Logic
- **Title:** Competing Dual BBS Modules (Legacy vs Phase 2 Suite)
- **Affected Files:**
  - `frontend/src/pages/BBSPage/BBSPage.jsx` (Legacy)
  - `frontend/src/pages/BBSPage/BbsProjectsPage.jsx` (Phase 2)
  - `frontend/src/pages/BBSPage/BbsWizardPage.jsx` (Phase 2)
  - `frontend/src/pages/BBSPage/BbsShapesPage.jsx` (Phase 2)
  - `frontend/src/pages/BBSPage/BbsReportsPage.jsx` (Phase 2)
  - `frontend/src/App.jsx` (lines 446–448 vs lines 509–523)
- **Description:**
  The frontend mounts both the older `BBSPage.jsx` monolith and the newer modular Phase 2 wizard suite.
- **Potential Impact:**
  User confusion, split feature updates, and redundant bundle weight.
- **Recommended Consolidation:**
  Retire `BBSPage.jsx` and consolidate routing exclusively onto the Phase 2 wizard.

### Issue ID: REB-P1-007
- **Severity:** P1 (High Impact)
- **Category:** Duplication / Backend / Service Logic
- **Title:** Dual Implementation of Batches & Optimizer Services (NestJS vs Express)
- **Affected Files:**
  - `backend/src/batches/batches.service.ts` (539 lines, NestJS Mongoose)
  - `backend/src/batches/batches.controller.ts` (72 lines, NestJS)
  - `backend/src/main.ts` (lines 3051–3350, Express native driver)
- **Description:**
  `batches.service.ts` implements a complete `commitBatch` and stock deduction engine using Mongoose. Simultaneously, `main.ts` lines 3070–3150 implements an almost identical `commitBatch` routine using the native MongoDB driver. Only the `main.ts` version executes at runtime.
- **Potential Impact:**
  Any bug fixes applied to `batches.service.ts` have zero effect in production.
- **Recommended Consolidation:**
  Delete or refactor `batches.service.ts` to be the single source of truth called directly by the active router.

### Issue ID: REB-P2-005
- **Severity:** P2 (Medium)
- **Category:** Duplication / Reporting / Utilities
- **Title:** Triplicate PDF & Duplicate Excel Export Engines
- **Affected Files:**
  - `backend/src/reports/reports.pdf.ts` & `reports.excel.ts`
  - `backend/src/attendance/attendance.export.ts` (48,904 bytes! Custom PDF & Excel builders)
  - `backend/src/casting/casting.pdf.ts`
  - `backend/src/drawings/drawings.transmittal.pdf.ts`
- **Description:**
  Rather than using a shared PDF template engine, `attendance.export.ts`, `reports.pdf.ts`, `casting.pdf.ts`, and `drawings.transmittal.pdf.ts` each implement independent PDFKit coordinate calculation, header rendering, table drawing, and page numbering.
- **Potential Impact:**
  Inconsistent styling, logos, fonts, and branding across exported company documents.
- **Recommended Consolidation:**
  Create a shared PDF document layout builder (`src/common/pdf/document-builder.ts`) that standardizes margins, headers, logos, and tabular grids.
