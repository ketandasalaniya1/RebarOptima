## 1. Executive Summary

This security audit inspects tenant boundaries, authentication mechanics, authorization checks, secret management, and exposure to common web application vulnerabilities (OWASP Top 10) in RebarOptima.

---

## 2. Critical Security Findings

### Issue ID: REB-P0-004
- **Severity:** P0 (Critical Vulnerability)
- **Category:** Security / Secret Management & Authentication Bypass
- **Affected Files:**
  - `backend/src/main.ts` (lines 716–717)
  - `backend/src/chat/chat.socket.ts`
  - `test-crm-acceptance.js` (line 10)
- **Evidence:**
  In `main.ts` lines 716–717:
  ```typescript
  const ACCESS_SECRET = process.env.JWT_ACCESS_SECRET || 'fallback-access-secret';
  const REFRESH_SECRET = process.env.JWT_REFRESH_SECRET || 'fallback-refresh-secret';
  ```
- **Problem:**
  If the application is deployed into a container or staging environment without an explicit `JWT_ACCESS_SECRET` environment variable, it defaults to the publicly known string `'fallback-access-secret'`.
- **Impact:**
  An attacker can forge valid JWT tokens for any arbitrary `userId`, role (`ADMIN`), or tenant (`companyId`), completely bypassing authentication and accessing all multi-tenant company data.
- **Recommendation:**
  Throw an immediate fatal startup error if `JWT_ACCESS_SECRET` or `JWT_REFRESH_SECRET` is undefined or equals known default strings when `NODE_ENV === 'production'`.

### Issue ID: REB-P1-009
- **Severity:** P1 (High Security Risk)
- **Category:** Security / CORS & Brute Force Protection
- **Affected Files:**
  - `backend/src/main.ts` (lines 54–60)
  - `backend/src/main.ts` (lines 1932–2000: `POST /api/auth/signin`)
- **Evidence:**
  In `main.ts` line 55:
  ```typescript
  res.header('Access-Control-Allow-Origin', '*');
  ```
- **Problem:**
  1. The API exposes a wildcard `Access-Control-Allow-Origin: *` while accepting bearer tokens.
  2. The `/api/auth/signin` endpoint has no IP-based or account-based rate limiting or lockout mechanism.
- **Impact:**
  - Vulnerability to credential stuffing and brute-force password guessing attacks.
  - Cross-site script access from malicious origins if an attacker leverages ambient network positioning.
- **Recommendation:**
  Configure a strict CORS allowlist matching official domains (e.g., `https://app.rebaroptima.com`). Implement `express-rate-limit` on `/api/auth/signin` (e.g., maximum 5 failed attempts per 15 minutes).

### Issue ID: REB-P1-010
- **Severity:** P1 (High Tenant Isolation Risk)
- **Category:** Multi-Tenancy / IDOR (Insecure Direct Object References)
- **Affected Files:**
  - `backend/src/projects/project-access.ts`
  - `backend/src/petty-cash/petty-cash.routes.ts`
  - `backend/src/contractors/contractors.routes.ts`
- **Evidence:**
  In `project-access.ts` lines 68–80:
  ```typescript
  let companyId = req.user?.companyId ? String(req.user.companyId) : null;
  // If not in token, falls back to querying userDoc
  ```
  In several routes, if `req.body.companyId` is provided, some updates check only `_id` without verifying that `companyId` matches `ctx.companyId`.
- **Problem:**
  Potential IDOR vulnerability where an authenticated user in Company A can read or update a record in Company B by passing Company B's `companyId` or record `_id`.
- **Impact:**
  Cross-tenant data leakage or unauthorized data manipulation.
- **Recommendation:**
  Strictly overwrite or validate `req.body.companyId` against `ctx.companyId` derived from the verified user session across all mutation endpoints.
