# 09. API INTEGRATION & CONTRACT AUDIT
**Project:** RebarOptima SaaS  
**Audit Date:** November 2026  
**Auditor:** Principal Integration & API Engineer  
**Status:** Audit Only — No Code Modifications

---

## 1. Executive Summary

The frontend interacts with the backend via `frontend/src/utils/api.js` (741 lines) using the native Fetch API.

The audit identifies:
1. **Inconsistent API response contracts** (mix of `{ success: true, data }` vs raw arrays vs `{ message }`).
2. **Missing unified error envelopes** causing inconsistent error handling on frontend forms.
3. **Simulated payment endpoints** in subscription management.

---

## 2. API Contract Inconsistency Matrix

| Endpoint Group | Success Format | Error Format | Authentication Required | Tenant Header (`X-Project-Id`) |
|---|---|---|---|---|
| `/api/auth/*` | `{ accessToken, refreshToken, user }` | `{ message }` | No (except `/refresh`) | Skipped |
| `/api/projects/*` | `{ success: true, data }` or `[...]` | `{ message, code }` | Yes | Explicit |
| `/api/inventory/*` | `{ standardStock, remnantsStock }` or `{ message }` | `{ message, code }` | Yes | Required |
| `/api/batches/*` | `{ batchName, ... }` or `[...]` | `{ message }` | Yes | Required |
| `/api/casting/*` | `{ success: true, data }` | `{ success: false, error }` | Yes | Required |
| `/api/crm/*` | `{ success: true, data }` | `{ success: false, error }` | Yes | Optional |
| `/api/chat/*` | `{ success: true, data }` | `{ message }` | Yes | Required |
| `/api/attendance/*`| `{ success: true, data }` | `{ message, code }` | Yes | Required |

### Issue ID: REB-P2-008
- **Severity:** P2 (Medium Integration Issue)
- **Category:** API Integration / Response Envelopes
- **Affected Files:**
  - `frontend/src/utils/api.js`
  - `backend/src/main.ts`
  - `backend/src/casting/casting.routes.ts`
- **Problem:**
  The backend lacks a standard response interceptor. Casting routes wrap responses in `{ success: true, data: ... }`, while Steel Inventory routes in `main.ts` return raw arrays or `{ standardStock, remnantsStock }`.
- **Impact:**
  Frontend developers must write custom unpacking logic for every single service, leading to repetitive `res.data || res` boilerplate and frequent `undefined` property crashes.
- **Recommendation:**
  Standardize all REST API responses into a unified JSend envelope:
  `{ success: boolean, data?: any, error?: { message: string, code: string } }`.
