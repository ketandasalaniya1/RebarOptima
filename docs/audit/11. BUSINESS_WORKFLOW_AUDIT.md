# 11. BUSINESS WORKFLOW & PROCESS INTEGRITY AUDIT
**Project:** RebarOptima SaaS  
**Audit Date:** November 2026  
**Auditor:** Construction ERP Business Analyst & QA Engineer  
**Status:** Audit Only — No Code Modifications

---

## 1. Executive Summary

This audit evaluates the end-to-end operational workflows connecting construction site activities to office reporting.

Key findings include:
1. **Broken Batch Reversal Workflow**: Deleting a batch permanently deletes the batch record but **fails to reverse stock deductions or remove created remnants**.
2. **Disconnected BBS-to-Cutting Optimizer Workflow**: BBS rebar items cannot be directly transferred into the Cutting Optimizer in one click without manual re-entry.
3. **Casting Material Shortage Blind Spot**: Casting approval does not halt if raw material stock (cement, aggregate) in Site Inventory is insufficient.

## 2. Detailed Workflow Findings

### Issue ID: REB-P0-005
- **Severity:** P0 (Critical Inventory & Data Integrity Defect)
- **Category:** Business Logic / Inventory Workflow
- **Affected Files:**
  - `backend/src/main.ts` (lines 3217–3240: `DELETE /api/batches/:id`)
- **Evidence:**
  In `main.ts` line 3222:
  ```typescript
  const result = await db.collection('batches').findOneAndDelete({ _id: new ObjectId(req.params.id), companyId });
  // Logs audit and immediately returns { deleted: !!result }
  ```
- **Problem:**
  When a batch is deleted:
  - Consumed standard stock bars are **never restored** to `stockitems`.
  - Usable remnant bars created by this batch are **never cleaned up** from `stockitems`.
  - Ledger transaction records in `inventory_transactions` are **never reversed**.
- **Impact:**
  Deleting a committed cutting batch causes irreversible physical-to-digital inventory divergence. Users must manually create fake inward stock adjustments to restore inventory levels.
- **Recommendation:**
  Implement a transactional batch cancellation workflow (`cancelBatch`) that:
  1. Inspects whether generated remnants have already been consumed in subsequent batches (reject deletion if consumed).
  2. Restores original stock bar quantities.
  3. Deletes or marks void the generated remnant records.
  4. Records balancing reversal entries in `inventory_transactions`.

### Issue ID: REB-P1-013
- **Severity:** P1 (High Operational Inefficiency)
- **Category:** Business Workflow / Cross-Module Integration
- **Affected Files:**
  - `frontend/src/pages/BBSPage/BbsWizardPage.jsx`
  - `frontend/src/pages/NewBatchPage/NewBatchPage.jsx`
- **Problem:**
  Once a Bar Bending Schedule is generated in the BBS module, there is no direct "Export to Optimizer" or "Create Cutting Batch from BBS" button. Site engineers must manually write down or retype hundreds of rebar part lengths, diameters, and quantities into the Cutting Optimizer page.
- **Impact:**
  - High probability of typographical errors during manual data transfer.
  - Substantial labor overhead on site engineering teams.
- **Recommendation:**
  Add a direct action in BBS (`Send to Cutting Optimizer`) that seeds `NewBatchPage` with the rebar schedule's required parts list.
