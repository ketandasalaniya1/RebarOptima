## 1. Executive Summary

This audit evaluates the system's performance characteristics across the frontend SPA bundle, Node.js event loop responsiveness, MongoDB query throughput, and concurrent multi-tenant scalability.

## 2. Key Performance Bottlenecks

### Issue ID: REB-P1-014
- **Severity:** P1 (High Concurrency & Event Loop Risk)
- **Category:** Backend Performance / Event Loop Blocking
- **Affected Files:**
  - `backend/src/main.ts` (lines 3059–3069: `POST /api/batches/optimize`)
  - `backend/src/batches/optimizer.engine.ts` (`solve1DCSP`)
- **Evidence:**
  `POST /api/batches/optimize` executes `solve1DCSP(stockRows, partsRows, options)` directly on the main Node.js event loop thread synchronously.
- **Problem:**
  Solving the 1D Cutting Stock Problem (an NP-hard combinatorial bin-packing problem) for large structural projects with 500+ rebar parts and multiple diameter groups requires significant CPU iterations.
- **Impact:**
  While `solve1DCSP` is calculating, the single-threaded Node.js event loop is completely blocked:
  - Incoming HTTP requests (such as attendance mark check-ins or chat messages) stall and experience latency spikes.
  - WebSocket pings can time out, causing Socket.IO clients to disconnect.
- **Recommendation:**
  Offload large optimizer computations to a Node.js `worker_threads` worker pool or a background task queue (e.g., BullMQ with Redis).

### Issue ID: REB-P2-011
- **Severity:** P2 (Medium)
- **Category:** Backend Performance / Latency Overhead
- **Affected Files:**
  - `backend/src/projects/project-access.ts` (lines 68–95: `resolveUserAndCompany`)
  - `backend/src/main.ts` (invoked on nearly every protected route)
- **Evidence:**
  `resolveUserAndCompany` executes `db.collection('users').findOne()` and `db.collection('roles').findOne()` on every authenticated HTTP request.
- **Problem:**
  For every API call made by the frontend, 2 database roundtrips are executed before the actual route logic begins.
- **Impact:**
  Adds an unnecessary 20–60 ms of network latency to every single API request.
- **Recommendation:**
  1. Embed `companyId` and `roleId` directly inside the JWT payload during token generation.
  2. Cache user role permissions in an in-memory LRU cache or Redis for the 15-minute token lifetime.

---

### Issue ID: REB-P2-012
- **Severity:** P2 (Medium)
- **Category:** Frontend Performance / Bundle Size
- **Affected Files:**
  - `frontend/src/App.jsx`
  - `frontend/package.json`
- **Problem:**
  All 31 application pages, CAD WebGL engines (`three`, `@mlightcad`), and secondary runtimes (`vue`, `element-plus`) are bundled into the primary JavaScript entry chunk without lazy loading.
- **Impact:**
  Initial page load payload exceeds 4 MB, degrading mobile 4G/5G performance on remote construction job sites.
- **Recommendation:**
  Implement route-level code splitting using `React.lazy()` for CAD, BBS Wizard, and Reports pages.
