# 13. Testing & Quality Assurance Audit
**Project:** RebarOptima SaaS Platform  
**Audit Date:** November 2026  
**Auditor:** Principal Software Architect & QA Lead  
**Scope:** Frontend tests, Backend unit tests, E2E acceptance test harnesses, static analysis, coverage gaps, and test integrity.

---

## 1. Executive Summary

The RebarOptima testing ecosystem presents an extreme asymmetry:
1. **Frontend Testing:** **0% Unit/Component/E2E Coverage.** No testing framework (Jest, Vitest, Playwright, Cypress) is installed or configured in `frontend/package.json`. There are zero test files in `frontend/src`.
2. **Backend Unit Testing:** 9 Jest test suites containing 54 tests run and pass in ~27 seconds (`npm test`). However, **2 of these 9 test suites** (`app.controller.spec.ts` and `projects.service.spec.ts`) exclusively test dead NestJS module code that is completely bypassed by the runtime Express engine in `main.ts`.
3. **Acceptance Test Scripts:** 9 monolithic Node.js integration scripts exist in the repository root (`test-*.js`). These test scripts require a live server, execute destructive database writes (creating projects, users, inventory, casting batches), lack assertions on data rollback, and cannot be run safely in CI/CD without polluting persistent storage.
4. **Engineering Logic Tests:** **0 unit tests** exist for the core cutting stock 1D-CSP optimizer (`optimizer.engine.ts`), BBS shape bend deduction algorithms (`bbs.service.ts`), or concrete casting mix design formulas (`casting.service.ts`).

## 4. Acceptance Test Scripts Analysis (Root Directory)

The repository root contains 9 manual integration scripts (`.js`):

1. `test-project-first-acceptance.js` (8 KB): Tests Scenarios A–E for Project-First architecture (create project, switch active project, header enforcement).
2. `test-crm-acceptance.js` (20 KB): Tests lead lifecycle, unit inventory blocking, booking voucher creation.
3. `test-general-inventory.js` (30.6 KB): Tests stock inward, purchase requisitions, dispatch gate passes.
4. `test-phase2-acceptance.js` (21.2 KB): Tests BBS generation and cutting optimizer API integration.
5. `test-phase3-acceptance.js` (32.4 KB): Tests casting workflow and pre-pour quality checklists.
6. `test-phase4-acceptance.js` (39.2 KB): Tests drawing revisions and CAD layer inspection.
7. `test-phase5-acceptance.js` (21.4 KB): Tests attendance regularization and biometric sync.
8. `test-phase6-integration.js` (33.3 KB): Tests end-to-end multi-module data flow.
9. `test-pm-acceptance.js` (12.1 KB): Tests task dependencies and CPM critical path calculation.

### 4.1 Flaws in Root Acceptance Scripts
- **Permanent Database Pollution:** Every script uses live `POST` endpoints with `Date.now()` naming. They do not clean up or rollback documents after execution. Running them on a staging/production database permanently pollutes company data.
- **Hardcoded Localhost Dependency:** Defaulting to `http://localhost:3000/api`. If the server is offline or fails, scripts crash with unhandled fetch errors.
- **No CI Integration:** None of these scripts are wired into `npm test` or automated GitHub Actions workflows.
- **Race Condition Vulnerabilities:** Several scripts use arbitrary `await new Promise(r => setTimeout(r, 1000))` delays instead of polling for asynchronous operation completion.

## 5. Critical Test Coverage Gaps

### 5.1 Engineering Calculations (Zero Tests)
- **Cutting Stock Optimizer (`optimizer.engine.ts` / `solve1DCSP`):**
  - No tests for kerf loss accumulation across N cuts.
  - No tests for stock length boundary edge cases (e.g., piece length > stock bar length).
  - No tests for remnant generation thresholds (min usable remnant length).
  - No tests for bin packing efficiency benchmarks.
- **Bar Bending Schedule (`bbs.service.ts` / `BBSWizard.jsx`):**
  - No unit tests for BS 8666 / IS 2502 bend deduction formulas:
    - 45° bend deduction: $1d$
    - 90° bend deduction: $2d$
    - 135° bend deduction: $3d$
  - No tests for total rebar tonnage calculation formula ($L \times D^2 / 162.28$).
- **Casting Mix Concrete Design:**
  - No tests for water-cement ratio variance, admixture dosage calculations, or 7-day vs 28-day compressive cube strength variance.

### 5.2 Multi-Tenant Security & Access Control (Zero Automated Tests)
- No automated tests verify that User A from `Company-1` is blocked from accessing documents belonging to `Company-2` via IDOR query injection (`GET /api/projects/:id` with foreign ID).
- No tests verify that the fallback JWT secret `'fallback-access-secret'` is rejected in production environments.
- No tests assert that Super Admin endpoints reject regular Tenant Admin tokens.

### 5.3 Frontend Unit & UI Regression (Zero Tests)
- **State Slices:** Redux slices (`projectSlice.js`, `authSlice.js`, `chatSlice.js`) have zero reducers/actions tests.
- **CAD Viewer Rendering:** `CADViewer.jsx` web worker DWG/DXF parser has zero mock rendering or WebGL context tests.
- **Project Switching:** Zero tests verify that changing the active project in Redux clears project-scoped caches in local component states.

---

## 6. Recommendations & Action Plan

1. **Adopt Vitest for Frontend (`P2`):** Install Vitest and React Testing Library in `frontend/` to test critical Redux state slices and project switching hooks (`useActiveProject.js`).
2. **Purge Dead Test Suites (`P2`):** Delete or refactor `app.controller.spec.ts` and `projects.service.spec.ts` so they test the active Express router rather than unused NestJS stubs.
3. **Build an Optimizer Calculation Test Suite (`P1`):** Write comprehensive unit tests for `optimizer.engine.ts` verifying kerf math, remnant generation, and stock deduction.
4. **Implement Ephemeral Test Database in Acceptance Scripts (`P1`):** Refactor the 9 root `test-*.js` scripts to run against a disposable MongoDB Memory Server (`mongodb-memory-server`) with automatic teardown after test execution.
