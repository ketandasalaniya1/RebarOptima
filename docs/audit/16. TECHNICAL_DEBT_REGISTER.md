# 16. Technical Debt Register
**Project:** RebarOptima SaaS Platform  
**Audit Date:** November 2026  
**Auditor:** Principal Software Architect  
**Scope:** Architectural, code quality, database, domain logic, and infrastructure technical debt register with estimated complexity and remediation priority.

---

## 1. Overview & Classification

Technical debt in RebarOptima has accumulated primarily due to rapid feature expansion ("Vibe Coding" velocity) where new modules were added alongside legacy modules rather than consolidating them.

### Complexity Legend:
- **Low (S):** 1–2 days effort, isolated file changes.
- **Medium (M):** 3–5 days effort, touches cross-cutting layers (frontend + backend).
- **High (L):** 1–2 weeks effort, requires schema migrations, multi-module refactoring, or architectural restructuring.
- **Critical (XL):** Multi-week architectural overhaul requiring regression testing across the entire platform.

## 3. Debt Retirement Strategy & Risk Matrix

### High-Impact, Low-Effort (Quick Wins — Phase 1):
1. **TD-DEVOPS-01 & TD-DEVOPS-02:** Remove in-memory fallback; align Docker environment variables to `MONGODB_URI`. (Eliminates P0 data loss risk in < 2 hours).
2. **TD-SEC-01:** Throw fatal error on missing JWT secrets. (Eliminates P0 auth forgery risk in < 1 hour).
3. **TD-LOGIC-01:** Fix optimizer kerf calculation formula. (Restores mathematical accuracy in < 2 hours).
4. **TD-DB-02:** Add compound MongoDB indexes on high-throughput collections. (Boosts database query speed 10x in < 2 hours).

### Strategic Refactoring (Phase 2 & 3):
1. **TD-ARCH-01:** Decompose `main.ts` into feature routers matching the existing modular architecture (`projects.routes.ts`, `batches.routes.ts`, etc.).
2. **TD-DB-03:** Consolidate the 5 disparate block collections into a single canonical `project_blocks` source of truth.
3. **TD-FE-01:** Migrate `App.jsx` to standard React Router DOM with lazy-loaded route chunks.
