## Change Entry 3: Milestone 3 — Cutting Optimizer Calculation Accuracy & Multi-Doc Safety

### 1. Issues Addressed
- **`REB-P1-012`**: Optimizer kerf loss overcounting ($N$ cuts vs $N-1$ cuts / physical cut counting).
- **`REB-P1-013`**: Remnant trim margin double deduction (trim applied repeatedly to already-trimmed offcuts).
- **`REB-P1-004`**: Multi-document transaction rollback wrapper for atomic operations.

### 2. Affected Files
1. `backend/src/batches/optimizer.engine.ts` (Lines 185–280)
2. `backend/src/batches/optimizer.engine.spec.ts` (Lines 85–125)
3. `backend/src/main.ts` (Lines 333–365)

### 3. Modifications Made
1. **Accurate Physical Kerf Accounting in `optimizer.engine.ts`:**
   - When candidate parts are tested during packing, kerf loss is calculated across the actual cuts between parts (`bar.parts.length * kerf`).
   - In waste and cuts counting: if leftover material exceeds kerf width, an additional physical cut is counted to detach the remnant/scrap, and kerf loss accounts for all physical cuts. If the bar is consumed with no leftover, cuts count is $(N - 1)$.
2. **Remnant Trim Margin Exemption in `optimizer.engine.ts`:**
   - When cutting from an offcut (`bar.isRemnant === true`), `barTrim` is set to `0`. Master bar trim allowance (`trimMargin * 2`) is no longer repeatedly deducted from offcuts that were already trimmed at initial fabrication.
3. **Multi-Document Atomic Transaction Helper in `main.ts` (`runWithTransaction`):**
   - Added a safe transaction executor that initiates a MongoDB session with `startTransaction()` and automatic `abortTransaction()` on errors when replica sets are available (e.g. MongoDB Atlas), while gracefully falling back to non-session operations on standalone or in-memory setups.
